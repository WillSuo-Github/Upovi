# Toolbar refresh and bulk updates, 0.4.2

The refresh button, Command-R and menu bar refresh share one operation: rescan the application directories, replace the old inventory, then check every discovered application against its configured sources. Search, sidebar selection and source filters do not restrict checking. Background P2P synchronization does not disable refresh; its old generation is cancelled and it resumes after the full refresh. Offline refresh still rescans and explains that source checks require a connection. Cancelling during scanning prevents the subsequent source-check phase.

The download icon is now **Update all**. It prepares one review of every source-confirmed, non-ignored update across the full inventory. One batch confirmation covers closing the listed applications and retaining backups. PKG system-side-effect wording is shown when the batch includes packages. Subsequent downloads, verification and installation run sequentially; administrator operations still use system authorization. No application is force-killed. Community reports never enter the plan.

The latest source target is selected, preferring a verifiable download for that same version/build when multiple sources exist. The batch does not silently substitute an older release. App Store apps, Upovi itself, unknown developer identity, missing integrity evidence and unsupported formats are listed with a manual reason and the appropriate update action. They are never counted as successfully installed. Existing signature, version, integrity, Gatekeeper, transaction, backup and administrator checks remain authoritative at execution time.

The sheet displays individual success, failure, cancellation or manual-update results. A failed download or installation does not prevent later applications from being attempted. Stop cancels an active download; after installation begins it lets that application finish before stopping subsequent work. A committed installation remains successful even when stop was requested meanwhile. Source checks, overlapping installs, restore/cleanup actions and self-update relaunch are excluded while the batch is under review or running.

Validation includes the complete 73-application plan, exclusion of forged/stale/mismatched-source candidates, ignored apps and manual channels, newest-target selection, failure continuation, download cancellation, stop after commit and manual-item nonexecution. Tests against the actual AppStore cover scan-before-check ordering over a replaced inventory despite active filters/background-sync state, cancellation between phases, bulk review scope/operation exclusion, offline start refusal, and production downloader failures finishing the queue without stale busy state. Tests use isolated preferences and synthetic paths; they do not update daily applications.

The local suite passed 95 tests (90 core and 5 actual-store workflow tests), and the same product revision passed CI on macOS 14 ARM, macOS 15 Intel and macOS 26 ARM. Native signed-app acceptance observed refresh rescan 71 applications and finish source checking with 9 source updates; the batch review showed 8 installable updates plus one manual item, disabled overlapping toolbar actions, and was cancelled without upgrading daily applications. Actual successful multi-app/administrator/PKG batch installation remains an acceptance boundary.

Native acceptance, signed artifact identity and CI results are recorded separately in [0.4.2 evidence](evidence/0.4.2-toolbar-updates.json). Earlier administrator/PKG and long-observation boundaries still apply. A successful unit test is not proof of real PKG execution or public update-feed acceptance.
